## 1. 总体架构

```
┌─────────────────────────┐   ┌─────────────────────────┐   ┌──────────────────┐
│ 学习端 Web (:3000)        │   │ 管理端 Admin (:3001)      │   │ uniapp (H5/小程序) │
│ Next.js 16 App Router    │   │ Next.js 独立应用          │   │ Vue3 + uni-app    │
│ 页面 + API 同进程         │   │ 页面 + API 同进程         │   │ 只调学习端 API     │
└───────────┬─────────────┘   └───────────┬─────────────┘   └────────┬─────────┘
            │        npm workspaces        │                          │
            └──────────▶ @grow/shared ◀────┘                          │
                     （Prisma/配置/AI库/邮件/日志/鉴权工具/类型）         │
                    ┌──────────────┐        ┌──────────────────┐     │
                    │ SQLite (WAL) │        │ app-config.json  │◀────┘ 无
                    │  /app/data   │        │  /app/config     │
                    └──────────────┘        └──────────────────┘
                     两端共享同一文件          学习端只读/管理端读写
                                             （AI Key、Prompts、SMTP、注册开关）
```

- **学习端与管理端各自是前后端一体的 Next.js 应用**，通过 npm workspaces 共享 `@grow/shared` 包（源码直引，Next `transpilePackages` 编译）。
- **数据同源**：两个进程打开同一个 SQLite 文件（WAL 模式 + 短事务保证并发安全）；`config/app-config.json` 同理，写入方只有管理端。
- **鉴权双实例**：两端各跑一套 NextAuth（Credentials + JWT），Cookie 名隔离（学习端 `next-auth.session-token`，管理端 `admin.session-token`）；管理端 `authorize()` 拒绝非 `admin` 角色，页面由 middleware 保护，API 层再用 `requireAdmin` 双保险。

## 4. AI 调用链路（核心）

所有 AI 能力收敛在 `@grow/shared/ai`：

```
业务路由 (/api/analyze 等)
   │  鉴权 → 限流(10次/分/用户) → 图片白名单/大小校验
   ▼
getAIService()  ← config.aiProvider（gemini | openai | azure）
   │
   ├─ GeminiProvider      @google/genai, generateContent + inlineData
   ├─ OpenAIProvider      openai SDK，兼容任意 OpenAI 格式服务（含 DeepSeek 等）；
   │                      LongCat 分支：非标多模态格式走裸 fetch 适配
   ├─ AzureOpenAIProvider Azure OpenAI SDK（deployment + api-version）
   │
   │  统一：retryOperation 重试 / pino 全量请求日志 / handleError 错误码映射
   ▼
能力方法（对应 prompts.ts 中的模板，可用 config.prompts.* 覆盖）
   ├─ analyzeImage        拍照识题：题干/选项/表格转录 + 四段解析 + 知识点标签（XML 标签输出 + zod 校验）
   ├─ detectQuestions     整页题目定位：只输出题号 + 百分比 bbox（JSON 数组），
   │                      前端框选某题后裁图再走 analyzeImage（/api/analyze/detect）
   ├─ generateSimilarQuestion  举一反三：同模块同考点变式题（easy~harder 四档）
   ├─ reanswerQuestion    重新解题：基于校正后的题干重出答案/解析
   └─ analyzeForGeogebra  判断题目是否适合 GeoGebra 动态演示并生成命令
```

要点：

- **标签预取**：识题前由 `tag-service.ts` 按学科/年级从数据库预取标签列表注入 prompt，保证知识点标签与系统标签库精确匹配。
- **错误码契约**：provider 层把上游错误映射为 `AI_AUTH_ERROR / AI_NOT_FOUND / AI_TIMEOUT_ERROR / AI_QUOTA_EXCEEDED / AI_CONNECTION_FAILED / AI_RESPONSE_ERROR / AI_SERVICE_UNAVAILABLE / AI_UNKNOWN_ERROR`，前端 `translations.ts` 按码转译为用户文案。
- **推理模型注意**：DeepSeek 等推理模型的 `reasoning_content` 也消耗 `max_tokens`，视觉调用建议 ≥8192。
- **配置优先级**：`config/app-config.json`（管理端界面，实时生效）> `.env` 环境变量。

## 5. 数据模型概览（prisma/schema.prisma）

核心模型：`User`（role: admin/user、educationStage/enrollmentYear 推导年级）→ `Subject`（错题本）→ `ErrorItem`（错题：题干/答案/解析/错因/图片 base64/掌握度 masteryLevel）↔ `Tag`（知识点）；练习侧：`PracticeQuestion`（题库，channel: free/similar/smart、ELO rating、状态机 pending/answered/discarded）与 `PracticeRecord`（作答记录，归因到 tag/errorItem/questionId）；另有 `ReviewSchedule`（复习计划）、`FocusSession`（专注时长）、`Announcement`、`Feedback`。

学习域算法库在**学习端** `src/lib/`（不进 shared）：`elo.ts`（题目难度等级分）、`diagnosis.ts` + `smart-practice.ts`（薄弱点诊断与定向出题，算法见 [薄弱点诊断算法说明](薄弱点诊断算法说明.md)）、`practice-choice.ts`（选择题解析）、`knowledge-tags.ts`（年级标签过滤）。

## 7. 前端要点

- **学习端 Web**：移动优先 + PWA（manifest + 深色模式 + 骨架屏）；上传识题工作区 `upload-workspace.tsx` 串起「上传 → 整页题目定位框选（`question-box-picker.tsx`）/ 自由裁剪（`image-cropper.tsx`）→ AI 识别 → 校对编辑器 → 保存 → 同图连续录题」；i18n 双语（`src/lib/translations.ts` + LanguageContext）。
- **uniapp**：`utils/request.ts` 统一封装（结构化错误、401 重登、小程序端自动维护 Cookie——NextAuth 会话依赖此机制）；`api/index.ts` 是唯一后端出口，与学习端共用同一套 REST。
- **限流**：AI 类接口按用户 10 次/分钟（内存令牌桶，`src/lib/rate-limit.ts`）。
- **前端日志**：`frontendLogger` 上报 `/api/logs/frontend`，便于排查端上问题。

## 8. 测试与质量

```bash
npm run test:unit         # vitest 单测（AI provider、领域算法等，343 例）
npm run test:integration  # 集成测试（API 路由，197 例）
npx playwright test e2e/upload-correction.spec.ts   # E2E（自动拉起 3000/3001 dev server）
npx tsc --noEmit          # 全仓类型检查
npm run lint              # eslint src
```

- E2E 用例必须**幂等**（自带数据创建与清理）；`auth-flow` 的用户管理段已迁管理端，暂标记 `test.fixme` 待管理端补用例。
- uniapp 无自动化测试，验证手段：`npm run build:h5` 构建 + H5 dev 手工/E2E 冒烟。

## 9. 关键设计决策（摘自拆分方案，改动前必读）

1. 学习端留在仓库根目录，不搞 `apps/*` 大搬家；共享范围收敛在 `shared/`。
2. 管理端独立 NextAuth + Cookie 隔离，API 双保险鉴权。
3. SQLite 双进程并发靠 WAL + 短事务；备份需注意 WAL checkpoint。
4. `app-config.json` 学习端只读、管理端唯一写入方。
5. 新增接口先对 [管理后台拆分方案 §2](管理后台拆分方案.md) 的归属表再动手：管理能力不回学习端，学习接口不泄管理配置。
