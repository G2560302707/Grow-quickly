# 小程序分享能力 · 交接文档

> 日期：2026-10-20
> 范围：微信小程序（`uniapp/`）的「发送给朋友」与「分享到朋友圈」能力，含配套的后端公开只读接口。
> 结论：分享能力**从零实现**并已本地构建通过；后端需重新发布后小程序侧才生效。

---

## 1. 背景与问题定位

### 1.1 现象

正式版小程序无法转发给好友，胶囊菜单里的「转发」是灰的；菜单里根本没有「分享到朋友圈」。

### 1.2 根因（不是故障，是从未实现）

改动前对 `uniapp/src` 全量检索，`onShareAppMessage` / `onShareTimeline` / `showShareMenu` / `open-type="share"` **0 处命中**（仅 `data-manage.vue` 的 `wx.shareFileMessage`，那是导出备份文件，与分享小程序无关）。

| 现象 | 直接原因 |
|---|---|
| 「转发」灰掉 | 页面未定义 `onShareAppMessage` |
| 无朋友圈入口 | 页面未定义 `onShareTimeline`，且从未调 `showShareMenu({menus:['shareAppMessage','shareTimeline']})` |
| 页内无分享入口 | 首页/我的页是 `navigationStyle: custom`，没有 `button open-type="share"`；小程序**不允许代码主动调起分享**，只能靠胶囊或该 button |

### 1.3 只补分享代码还会踩的坑（本次一并解决）

1. **详情页分享出去对方打开必报错**：`api/index.ts` 的 `getErrorItem` 在游客态走 `demo.findDemoItem(id)`，真实 id 抛「演示数据中未找到该错题」。
2. **朋友圈是「单页模式」**，不是小程序：`scene === 1154`，无登录态、`wx.login` 不可用、**禁止一切路由跳转**、tabBar 不渲染、`button open-type` / `showShareMenu` 等被禁用。
3. 无 5:4 分享图资源；不传 `imageUrl` 会截取页面快照。
4. 原图以 `data:image/...;base64` 存库，微信 `imageUrl` **不接受 data URL**。

## 2. 方案总览

```
详情页「分享」 ──onShareAppMessage──▶ /pages/share/share?id=<itemId>&t=<token>
                                        │  （公开只读接口，无 session）
好友/未登录用户打开 ◀──────────────────┘
                                        │
                     「转给同学」= open-type="share"（转发分享页本身）
                     朋友圈 = 右上角「···」→ 分享到朋友圈（单页模式打开本页）
```

设计决策（重要，改动前先读）：

| 决策 | 原因 |
|---|---|
| 内容落到独立页 `pages/share/share`，不直接分享 `detail` 页 | `detail` 依赖登录态；单页模式无登录，必须有一个无鉴权的内容页 |
| 详情页**不定义** `onShareTimeline` | 朋友圈只能分享「当前页」；一旦定义，好友在朋友圈打开 `detail` 会因未登录报错 |
| 分享鉴权用 HMAC 签名令牌，不用 session | 单页模式无 Cookie/无 `wx.login`；令牌与 itemId 绑定，越权无效 |
| 公开接口只回白名单字段 | 分享是"公开可见"语义，绝不能带出 `userNotes`/`mistakeAnalysis`/`masteryLevel`/用户标识 |
| 分析/专注/统计/练习页不开放转发 | 交互型页面，单页模式必坏，且存在诱导/违规审核风险 |

页面策略：

| 页面 | 发给朋友 | 朋友圈 |
|---|---|---|
| `pages/index/index` | ✅ 品牌名片，`path=/pages/index/index` | ✅ 品牌文案（不带头像/个人数据） |
| `pages/detail/detail` | ✅ 落到 `pages/share/share` | ❌ 见上表 |
| `pages/share/share` | ✅ 转发分享页自身 | ✅ 主载体（内容型页面） |
| 其余页面 | ❌ 不定义 handler | ❌ |

## 4. 接口契约

### 4.1 `GET /api/share/error-items/[id]?t=<token>`（公开，无 session）

成功 200：

```json
{
  "id": "cuid",
  "questionText": "题干 markdown/latex",
  "answerText": "正确答案",
  "analysis": "AI 解析",
  "wrongAnswerText": "错答",
  "imageUrl": "data:image/jpeg;base64,... 或 null",
  "subjectName": "数量关系",
  "tagNames": ["工程问题", "赋值法"],
  "createdAt": "2026-10-01T00:00:00.000Z"
}
```

错误：

| 状态 | message | 触发 |
|---|---|---|
| 400 | 缺少分享内容标识 | id 为空 |
| 403 | 分享链接已失效，请让对方重新分享 | 令牌缺失 / 伪造 / 过期（统一文案，不区分，防探测） |
| 404 | 分享的内容不存在或已被删除 | 题目已删 |
| 500 | 分享内容加载失败，请稍后重试 | 数据库异常（已记日志） |

注意：**该接口永不返回 401**。前端 `request()` 遇到 401 会 `reLaunch` 到登录页，在单页模式下会造成白屏。

### 4.2 `GET /api/error-items/[id]`（既有，已登录）

响应在原对象基础上多一个字段 `shareToken`（字符串，密钥缺失时为空串）。旧调用方不受影响。

## 5. 关键实现细节

**分享图**：详情页 `originalImageUrl` 是 data URL，微信 `imageUrl` 不接受。`prepareShareImage()` 在小程序端把它 base64 解码写入 `${wx.env.USER_DATA_PATH}/share-cover.<ext>`，返回本地路径；任一步失败回落 `static/share/share-cover.png`。因 `onShareAppMessage` 必须**同步**返回，落盘在 `onLoad` 里预置（fire-and-forget）。

**菜单开启时机**：`enableShareMenu()` 在 `App.onLaunch`、`index.onShow`、`share.onShow` 各调一次（避免切页后菜单被重置），内部先判断单页模式直接 return（单页模式下 `showShareMenu` 被微信禁用）。

**朋友圈为何无按钮**：微信未开放"代码直接调起朋友圈"，只能由右上角菜单发起，`open-type="share"` 只会调起"发送给朋友"。故分享页只给路径提示文案，且不做诱导（审核红线）。

**单页模式的降级**：`isSinglePageMode()` 用 `uni.getEnterOptionsSync().scene === 1154` 判断；为真时隐藏所有 `navigateTo/reLaunch` 与 `open-type` 入口，底部改为文字引导，依赖微信原生「前往小程序」操作栏。误判的后果仅为少一个按钮，不会崩。

## 6. 部署与发布

1. **先发布后端**（根目录）：新增 route 与 `shareToken` 字段。未发布时小程序分享卡拿不到令牌，会退化成"首页名片"。
2. 可选环境变量 `SHARE_TOKEN_SECRET`（不配则用 `NEXTAUTH_SECRET`）。**不要**在不改代码的情况下同时删掉两者，否则分享链路整体失效。
3. 小程序：`cd uniapp && npm run build:mp-weixin` → 开发者工具导入 `dist/build/mp-weixin` → 上传体验版 → 提审。
4. 无需在小程序后台新增域名（沿用 `https://after7lab.cloud` 的 request 合法域名）。
5. 提审说明建议：「分享功能用于同学之间分享错题与解析，朋友圈为纯内容页，无任何用户隐私数据与诱导分享」。

## 7. 验收清单（真机，正式版或体验版）

1. 首页 →「我的错题本」右侧「分享」→ 出现转发面板（不再灰）。
2. 详情页 → 题目卡右上「分享」→ 分享给另一个微信小号 → 对方**未登录**打开，能看到题干/答案/解析，不是「演示数据中未找到该错题」。
3. 首页胶囊「···」→ 出现「分享到朋友圈」（微信 Android/iOS ≥ 8.0.24，基础库 ≥ 2.11.3）。
4. 朋友圈打开 → 为单页模式：顶部微信导航、底部「前往小程序」、页面无 tabBar、无跳转按钮，内容完整；点击底部按钮可进入完整小程序。
5. 分享页胶囊 →「分享到朋友圈」可用，卡片标题为题干摘要、图为题目原图。
6. 令牌过期：把 `t` 改一个字符 → 页面提示「这个分享打不开了 / 分享链接已失效」，不白屏。
7. 删除该错题后再打开旧分享 → 提示「分享的内容不存在或已被删除」。
8. 后台日志无异常；`/api/share/*` 请求状态码正常。

## 8. 已知限制 / 折衷

| 限制 | 说明 / 后续方向 |
|---|---|
| 详情页不能直接发朋友圈 | 微信只能分享当前页，而 `detail` 需登录。若产品上必须支持，方案是让 `detail` 支持 `?t=` 只读模式（隐藏笔记/掌握度/编辑），成本约 0.5 天，需评估隐私边界 |
| 想发"这道题"到朋友圈的实际路径 | 详情页分享给好友（或自己）→ 从会话打开分享页 → 右上角发朋友圈；或首页发品牌卡 |
| 单页模式转化弱 | 微信禁用跳转与 `open-type`，只能靠原生「前往小程序」，属平台限制 |
| 令牌与内容不联动 | 分享后编辑题目，卡片标题仍是旧摘要，落地页内容是新内容（可接受） |
| 无分享频率限制 | 目前仅令牌门禁；如需防刷可在 `/api/share/*` 挂 `rate-limit` |
| 分享统计缺失 | 未记录分享次数/来源 scene；后续可在分享接口按 scene 打点 |

## 10. 回滚方式

- 小程序侧：删除 `pages.json` 的 `pages/share/share` 条目 + 三个页面的 `onShareAppMessage`/`onShareTimeline` + 两个「分享」按钮，即回到"不可分享"状态（残留的 `utils/share.ts`、`api/index.ts` 方法、静态资源无副作用）。
- 后端侧：删除 `src/app/api/share/**` 与 `src/lib/share-token.ts`，并撤回 `error-items/[id]` GET 里的 `shareToken`（不撤也不影响既有功能，只是多一个字段）。
- 先回滚小程序、后回滚后端是安全的；反向会让分享卡落地 404。
