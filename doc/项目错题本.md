## 2026-10-14

### 1. 误把打包产物提交进 git（tar 186MB + zip 346MB）
- **现象**：`git push` 反复报 `RPC failed; curl 55 / Connection was reset`，直连也超时；推送载荷高达 ~531 MB。
- **根因**：仓库目录里有 `wrong-notebook.tar`（185MB）、`deploy/bundle.zip`（346MB）两个打包产物，`git add -A` 把它们整体提交进了 `d413897`；事后虽 `git rm --cached` 移出 HEAD，但 **git 历史不可变**，推送时远端没有这两个 blob，仍必须整块上传。
- **处理**：
  1. 加入 `.gitignore`（`deploy/bundle/*.zip`、`*.tar`、`wrong-notebook*.tar` 等）；
  2. `git rm --cached` 移出跟踪；
  3. 因提交尚未推送过，直接**重写本地历史**摘掉坏提交：
     `git rebase --onto <好提交> <坏提交> HEAD` → `git branch -f main <新提交>` → `git switch main`；
  4. `git reflog expire --expire=now --all && git gc --prune=now` 回收 ~2.4GB 本地对象。
- **预防**：`git add` 前先 `git status` 看有没有大文件；必要时先 `git rev-list --objects --all` 排查大对象。

### 2. 部署模板里的真实密钥（潜在泄露）
- **现象**：`deploy/bundle/.env.prod` 中出现疑似真实值 `WECHAT_APP_SECRET="（已打码，勿外泄）"`、`appid=wx571724ac4670bcd7`。
- **结论**：该文件当前被 `.gitignore` 忽略，git 历史中也从未出现过 → **未入库，安全**。
- **注意**：别在手动打包 `deploy/bundle` 目录转发他人时把 env 一起带走；若该 secret 曾暴露到聊天记录/网盘等渠道，应去微信公众平台重置。

### 3. Next.js 16 中间件返回语义变化导致测试全红
- **现象**：`npm run test:unit` 5 个失败（middleware 4 个 + config 1 个）。
- **根因**：Next.js 16 中间件"放行"时不再返回 `undefined`，而是返回带 `x-middleware-next: 1` 头的 `Response`；且 config 默认 AI provider 实为 `openai`，测试却断言 `gemini`。
- **处理**：更新断言为"非重定向即放行"（`expectAllowed` helper），config 期望改为 `openai`；重跑后 27 文件 / 376 用例全绿。
- **预防**：升级框架/依赖后先跑全量测试，别沿用旧返回语义假设。

### 4. 全局 git 代理导致的推送失败
- **现象**：`git push` 报 `Connection was reset`；去掉代理直连又超时。
- **根因**：全局 git 配置里 `http.proxy/https.proxy = http://127.0.0.1:7890`（Clash），Clash 未开或链路不稳时必失败；国内直连 GitHub 也不一定通。
- **处理**：按次覆盖、不动全局配置：`git -c http.proxy= -c https.proxy= push origin main:main`。
- **预防**：推送前确认 Clash 开着，或显式直连；网络不稳时多试几次。
