# 部署文档（Docker 为主）

> 适用范围：**学习端 Web（含后端 API）** 与 **管理端 Admin** 的生产/自托管部署。
> uniapp 小程序端目前为规划阶段（域名备案、内容安全合规等前置条件未完成），部署时无需考虑；H5 端仅用于开发预览，不参与生产部署。
> 相关文档：[技术文档](技术文档.md)、[功能文档](功能文档.md)、[目录结构](目录结构.md)、[管理后台拆分方案](管理后台拆分方案.md)

## 1. 部署架构总览

```
                    ┌──────────────────────────────┐
   用户/浏览器 ───▶  │  学习端 wrong-notebook  :3000 │────┐
                    │  (Next.js 前后端一体)         │    │
                    └──────────────────────────────┘    │
                    ┌──────────────────────────────┐    │   ┌──────────────────────┐
   管理员/浏览器 ──▶ │  管理端 wrong-notebook-admin :3001│────┼──▶│ SQLite  /app/data    │
                    │  (Next.js 前后端一体)         │    │    │ (卷挂载 ./data)      │
                    └──────────────────────────────┘    │   └──────────────────────┘
                                                        │   ┌──────────────────────┐
                                                        └──▶│ app-config.json      │
                                                            │ (卷挂载 ./config)    │
                                                            └──────────────────────┘
```

- **两个容器各自是前后端一体的 Next.js 应用**（页面 + API 同进程），没有独立的"后端服务"需要单独部署。
- 两个容器**共享同一个 SQLite 数据库**（`./data/dev.db`，已开 WAL）与同一份**应用配置** `./config/app-config.json`（学习端只读、管理端读写）。
- 端口：学习端 `3000`，管理端 `3001`（管理端建议只在内网/VPN/白名单环境暴露）。

## 2. 前置要求

| 项目 | 要求 |
|---|---|
| 宿主机 | Linux / macOS / Windows（Docker Desktop）均可 |
| Docker | 20.10+，Compose v2（`docker compose version` 可用） |
| 端口 | 3000（学习端）、3001（管理端）、443/80（HTTPS 可选）未被占用 |
| 会话密钥 | 执行 `openssl rand -base64 32` 生成一个 `NEXTAUTH_SECRET` |
| 磁盘 | 镜像约 300–500MB，另为数据库预留空间（含用户上传图片 base64，增长较快时定期清理错题图片） |

> **国内网络拉取镜像慢/失败**：基础镜像是 `node:22-alpine`，可先从加速源拉取并重打标签，再执行构建/拉取：
> ```bash
> docker pull docker.m.daocloud.io/library/node:22-alpine
> docker tag docker.m.daocloud.io/library/node:22-alpine node:22-alpine
> ```

## 3. 方式一：Docker Compose（推荐）

`docker-compose.yml` 已包含两个服务：

- `wrong-notebook`：学习端，默认拉取预构建镜像 `ghcr.io/wttwins/wrong-notebook:latest`；
- `wrong-notebook-admin`：管理端，**始终本地构建**（构建上下文为仓库根目录）。

### 3.1 步骤

```bash
# 1) 准备目录（与 compose 的卷挂载对应）
mkdir -p data config

# 2) 修改 docker-compose.yml 中的 NEXTAUTH_SECRET（两个服务都要改，保持一致）
#    NEXTAUTH_SECRET=<openssl rand -base64 32 的结果>

# 3) 启动（首次会自动构建管理端镜像）
docker compose up -d

# 4) 观察初始化日志（数据库迁移、种子、管理员账号都在这一步完成）
docker compose logs -f wrong-notebook

# 5) 访问
#    学习端  http://<你的IP>:3000
#    管理端  http://<你的IP>:3001
```

### 3.2 首次启动会自动做什么（docker-entrypoint.sh）

1. 检查 `/app/data/dev.db` 是否存在，不存在则初始化空库；
2. 执行 `prisma migrate deploy` 同步表结构；
3. 运行管理员种子脚本，确保 `admin@localhost` 存在且角色正确；
4. 版本号变化时自动重建系统标签（知识点标签与代码版本同步）。

> **默认管理员**：`admin@localhost` / `123456` —— **首次登录后立即到管理端修改密码！**

### 3.3 首次配置 AI（必须）

镜像内**不包含任何 AI 密钥**（`config/` 已被 .dockerignore 排除，不会被打入镜像）。首次部署后：

1. 用管理员账号登录管理端 `http://<IP>:3001`；
2. 进入 **系统设置 → AI 供应商**，配置 Gemini / OpenAI（及任意兼容接口）/ Azure OpenAI，保存即生效；
3. 配置写入 `./config/app-config.json`（宿主机文件，容器重启不丢）。

不配置 AI 时，学习端除 AI 相关功能（拍照识题、AI 解题、练习出题）外均可正常使用。

## 4. 方式二：全本地构建（不依赖 ghcr.io 预构建镜像）

仓库根目录提供了 override 文件 `docker-compose.build.yml`：

```bash
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```

学习端镜像会在本机构建（管理端本就本地构建），数据卷、配置卷与主 compose 完全一致。

也可以单独构建镜像：

```bash
docker build -t wrong-notebook:local .          # 学习端
docker build -f admin/Dockerfile -t wrong-notebook-admin:local .   # 管理端
```

> **管理端镜像构建注意**：`admin/Dockerfile` 的构建上下文必须是**仓库根目录**（它要引用根目录的 `prisma/`、`shared/`），不要进到 `admin/` 目录里执行 `docker build`。

## 5. 方式三：纯 docker run（只要学习端）

```bash
docker run -d --name wrong-notebook \
  -e NEXTAUTH_SECRET="your_secret_key" \
  -e AUTH_TRUST_HOST=true \
  -p 3000:3000 \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/config:/app/config \
  ghcr.io/wttwins/wrong-notebook
```

此方式没有管理端容器，AI 配置只能通过手动编辑 `./config/app-config.json` 完成（字段结构见 `shared/src/config.ts` 的 `AppConfig` 类型）。

## 6. 环境变量（部署相关）

| 变量 | 必填 | 说明 |
|---|---|---|
| `NEXTAUTH_SECRET` | ✅ | 会话签名密钥，两个服务**必须一致**；用 `openssl rand -base64 32` 生成 |
| `NEXTAUTH_URL` | 建议 | 对外访问地址（如 `https://notebook.example.com`）；不固定 IP/走反代时可省略并用 `AUTH_TRUST_HOST=true` |
| `AUTH_TRUST_HOST` | 建议 `true` | 让 NextAuth 从请求头推断地址，容器/反代环境必备 |
| `DATABASE_URL` | 容器内已内置 | 默认 `file:/app/data/dev.db`，一般不需要改 |
| `APP_CONFIG_PATH` | 管理端已内置 | `/app/config/app-config.json` |
| `LOG_LEVEL` | 可选 | `trace/debug/info/warn/error/fatal`，生产建议 `info` |
| `HTTP_PROXY` / `HTTPS_PROXY` | 可选 | 宿主机需要代理访问 AI 上游时设置（学习端容器） |
| `HTTPS_ENABLED` / `CERT_DOMAIN` | 可选 | 仅内置 HTTPS 部署方式使用，见 §8 |
| `OPENCLAW_*` | 可选 | 对接本地 Openclaw agent 的批量错题导入，普通部署忽略 |

> 学习端 `.env` 里的其他 AI 环境变量（`AI_PROVIDER`、`GOOGLE_API_KEY` 等）是**兜底默认值**；`config/app-config.json`（管理端界面配置）优先级更高，生产环境推荐统一走管理端配置。

## 7. 数据持久化与备份

| 宿主机路径 | 容器内路径 | 内容 |
|---|---|---|
| `./data` | `/app/data` | `dev.db`（全部业务数据）、`.app_version`（版本标记） |
| `./config` | `/app/config` | `app-config.json`（AI 供应商/实例、Prompts、SMTP、注册开关、超时） |

**备份**（建议停写窗口执行，SQLite WAL 模式下热拷贝可能丢最近事务）：

```bash
# 学习端容器内执行 checkpoint 后，宿主机直接复制
docker exec wrong-notebook sh -c "node -e \"require('/app/node_modules/@prisma/client')\"" 2>/dev/null  # 可选
docker stop wrong-notebook
cp data/dev.db backup/dev.db.$(date +%F)
cp config/app-config.json backup/
docker start wrong-notebook
```

**恢复**：停容器 → 用备份覆盖 `data/dev.db` 与 `config/app-config.json` → 启动容器（entrypoint 会自动把 schema 迁移到当前版本）。

## 8. HTTPS 部署（内置，无需额外反代）

`docker-compose.https.yml` 使用镜像内自带的 HTTPS 代理（`https-server.js`，监听 443，反代到应用 3000）：

```bash
# 局域网（自动生成自签名证书，10 年有效期）
CERT_DOMAIN=192.168.1.100 docker compose -f docker-compose.https.yml up -d
# 访问 https://192.168.1.100 ，首次点击"高级 → 继续"

# 自有证书：把 cert.pem / key.pem 放入 ./certs/ 目录后再启动
# 公网正式环境：建议用 certbot 签发后放入 ./certs/，或直接用 Nginx/Caddy 反代并停用内置 HTTPS
```

> 需要 HTTPS 的原因：学习端的拍照识题依赖浏览器摄像头/文件访问的安全上下文策略；PWA 安装同样要求 HTTPS。

## 9. 版本升级

```bash
docker compose pull          # 拉取最新镜像（预构建方式）
docker compose up -d         # 重建容器
docker compose logs -f wrong-notebook
```

entrypoint 检测到 `package.json` 版本变化时会自动：执行增量迁移 → 校准管理员账号 → 重建系统标签。**数据库与配置在卷里，升级不丢数据。**

---

## 10. 管理端安全建议

管理端掌握用户管理、AI 密钥、邮件账号、系统重置等敏感能力：

1. **不要直接暴露公网**：只在内网/VPN 使用，或在反代层对 `:3001` 加 IP 白名单 + Basic Auth；
2. 管理端与学习端使用**独立会话 Cookie**（`admin.session-token` / `next-auth.session-token`），互不越权；
3. 管理端仅 `role=admin` 的账号可登录，普通用户登录会被拒绝。

## 11. 本地开发环境（非 Docker）

Windows 一键脚本（双击运行）：

- **`启动测试.bat`**：检查 Node → 安装依赖 → 初始化数据库/迁移 → 复制 `.env` → 拉起**学习端 ：3000** 与 **管理端 ：3001** 两个窗口，并自动打开浏览器；
- **`停止服务.bat`**：按端口（3000/3001/5173）结束本项目的 dev 进程。

手动方式：

```bash
npm install                     # npm workspaces：同时装好根、shared、admin 的依赖
cp .env.example .env            # 学习端环境变量
cp admin/.env.example admin/.env
npx prisma generate && npx prisma migrate dev && npx prisma db seed

npm run dev                     # 学习端 http://localhost:3000
npm run dev -w @grow/admin      # 管理端 http://localhost:3001
npm run dev:h5 --prefix uniapp  # uniapp H5 http://localhost:5173（/api 代理到 3000，开发预览用）
```

## 12. 常见问题排查

| 现象 | 排查 |
|---|---|
| 容器反复重启 | `docker compose logs wrong-notebook`，多为 `data/` 目录权限问题（Linux 宿主机注意 UID 1001 可写） |
| 登录后刷新就掉线 | `NEXTAUTH_SECRET` 未设置或两个服务不一致；反代环境未设 `AUTH_TRUST_HOST=true` |
| AI 识题/出题报错 | 管理端 `/settings` 检查 AI 实例的 Key/域名/模型名；看学习端日志中的 AI 4xx/5xx 与错误码（`AI_AUTH_ERROR`=Key 错、`AI_NOT_FOUND`=模型名错、`AI_TIMEOUT_ERROR`=上游超时） |
| 拍照识题无法调起摄像头 | 必须 HTTPS（见 §8），或本机 localhost 开发环境 |
| 拉取镜像超时 | 见 §2 的镜像加速说明 |
| 管理端打不开 | 学习端容器必须先启动（数据库迁移和种子由它负责）；确认 3001 端口已放行 |
