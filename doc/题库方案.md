# 题库方案（离线收录 + 分类 + 检索出题）

> 目标：解决"练习出题全靠 AI 实时生成，一次 10~60 秒"的速度与成本问题。管理员平时找到题目资源后批量导入，系统离线完成收录、分类（模块 / 考点 / 难度）、去重与审核；用户出题时**先查题库直接命中（毫秒级、零 AI 成本），未命中再回退现有 AI 生成管道**。
>
> 结论先行：**能实现，且不需要推翻现有架构**。题库是一个新数据层（`BankQuestion`），叠加在现有练习管道之上；现有的标签体系、四档难度、Elo 难度选择、二元组去重、生成即入库，全部直接复用。AI 实时生成保留为兜底，题库为空时系统行为与现在完全一致。
>
> **实施状态（2026-10-07，P0 + P1 已完成并冒烟验证）**：
> 1. 行测五大模块考点标签树（`shared/src/tag-data/gongkao.ts`，91 个系统标签，`scripts/seed-gongkao-tags.ts` 幂等 seed，已接入 Dockerfile/entrypoint）；
> 2. 数据模型 `BankQuestion` + `BankImportBatch`（含 `raw → pending → published/disabled` 生命周期与 `parse_lock` 抢占锁），`PracticeQuestion.bankQuestionId` 关联（迁移 `20261007100000` / `20261007110000`）；
> 3. AI 批量解析：`generateBankImportPrompt` + `parseBankQuestions` 落在三个 provider（OpenAI/Gemini/Azure），结果容错解析 `parseBankImportBatch`；
> 4. 管理端 `/bank` 题库管理页（导入+进度续跑 / 审核工作台 / 覆盖度统计）与 `/api/bank/*` 五个接口；
> 5. 出题链路：`POST /api/practice/smart` 题库优先（考点子树 ∩ 已发布 ∩ 单选 ∩ 非图形 ∩ 难度±一档 ∩ 用户没做过），AI 配额只在真正调 AI 时扣；作答经 `practice/record` 回写 `attemptCount/correctCount`；
> 6. 双端「题库」来源徽标（web pool + uniapp pool）；
> 7. 错题识别（analyze）行测标签注入：行测错题本不再映射 K12 学科，注入 gongkao 考点清单；
> 8. 冒烟结果：导入 2 题 → DeepSeek 一次调用 7.9s 完成解析分类（数量关系/工程问题、判断推理/数量规律）自动发布；smart 出题命中题库 956ms 返回；作答回写统计正确。
> 偏差说明：导入切分新增 `raw` 状态（方案原文 pending 起步）；检索额外过滤 `questionType=single`；审核策略落地为"默认直接发布 + 低置信度/疑似重复/无考点强制待审"。

## 1. 现状与痛点

当前出题链路全部实时调 AI：

| 场景 | 接口 | 现状 |
|---|---|---|
| 举一反三 | `POST /api/practice/generate` | 锚定原错题，单次 AI 调用，10~60s |
| 薄弱点专项 | `POST /api/practice/smart` | 锚定薄弱考点+多道错题，最坏**两次**调用（相似度过高时重生成一次） |
| 限流 | `src/lib/rate-limit.ts` | AI 接口每用户 10 次/分钟 |

每次出题都是"花钱 + 等待"，且同一考点反复练习时 AI 可能产出重复或质量漂移的题。

但已有的基建对题库方案非常有利：

- `PracticeQuestion`（prisma/schema.prisma:219）**生成即入库**，有待做/已做/已弃生命周期与 pool 页面（web + uniapp 双端都有）；
- `KnowledgeTag` 层级标签系统（isSystem 系统标签 + 用户自定义）；
- 四档难度 `easy|medium|hard|harder` 与 `src/lib/elo.ts` 的按能力分选难度；
- `bigramSimilarity`（src/lib/smart-practice.ts:63）字符二元组去重。

## 2. 总体设计

```
【离线·慢没关系】                          【在线·要快】
管理员找题 → 导入(粘贴/文件)               出题请求(smart / 自由练习)
   ↓ 题号正则切分                                ↓
   ↓ AI 批量解析(每批5题,后台推进)          ① 查题库: 考点子树+难度+用户没做过
   ↓ 去重(hash精确 + bigram近重复)              → 命中: 直接建 PracticeQuestion 返回
   ↓ 审核列表(管理员确认/改分类)                 (毫秒级, 零AI成本)
   ↓                                        ② 未命中/库存不足
BankQuestion(全局题库,所有用户共享)  ────→      → 回退现有 AI 生成管道(代码不动)
                                               生成题继续入库 PracticeQuestion
```

关键决策：

1. **全局题库与用户题库分离**：`BankQuestion` 是系统资产（所有用户共享，无 userId）；`PracticeQuestion` 继续作为用户维度的"做题实例"（谁抽到、做没做、对错），通过新增 `bankQuestionId` 关联。用户数据隔离模型不变。
2. **AI 生成保留为兜底**：题库未命中时走现有管道，用户体验只升不降；冷启动（题库空）行为与现状完全一致。
3. **慢的部分全部离线**：解析、分类、去重都在导入时完成，不占用户请求时间。

## 3. 分类体系（怎么分）

四个维度，全部向下兼容现有字段：

### 3.1 模块（一级）
复用 `AI_SUBJECT_OPTIONS` / `GONGKAO_NOTEBOOKS`：言语理解、判断推理、数量关系、资料分析、常识判断（+ 申论）。决定题挂在哪个练习入口下。

### 3.2 考点标签（二级，1 主 + ≤4 辅）
复用 `KnowledgeTag`（挂 `isSystem=true` 系统标签）。检索时按"该考点及其子树"匹配。示例结构：

```
言语理解：逻辑填空 / 片段阅读(主旨概括·细节判断·词句理解) / 语句表达(语句排序·语句填空) / 篇章阅读
判断推理：图形推理 / 定义判断 / 类比推理 / 逻辑判断(削弱加强·翻译推理·分析推理·真假话...)
数量关系：基础应用题 / 行程问题 / 工程问题 / 经济利润 / 排列组合 / 几何问题 / 最值问题 ...
资料分析：增长率 / 增长量 / 比重 / 平均数 / 倍数 / 隔年增长 / 年均增长 ...
常识判断：政治 / 法律 / 经济 / 历史 / 地理 / 科技 / 时政 ...
```

主考点用于出题检索（`primaryTagId`），辅考点存 JSON 数组（`extraTagIds`），参与诊断统计。

> ⚠️ **前置工作（P0）**：`shared/src/tag-data/` 目前只有 K12 学科标签（math/chinese…），**没有行测考点树**。需要先补一套行测系统标签 seed。这同时能修正一个现存问题——错题识别 prompt 里行测题的 `knowledge_points_list` 注入的是 K12 标签清单（prompts.ts 的 else 分支），行测标签树建好后 analyze 打标也会更准。

### 3.3 难度（三级）
与现有四档一致：`easy | medium | hard | harder`。

- **初始标定**：导入解析时 AI 按国考/省考真题标准打档（批量解析不赶时间，可附评分理由）；
- **动态校准**：`attemptCount / correctCount` 随真实作答累计，每题实际正确率落在区间外时（如 ≥75% 建议降一档、≤35% 建议升一档，≥20 次作答才生效）给出调档建议，P2 再做自动调档；
- **与 Elo 衔接**：smart 出题本来就用 `difficultyForRating(elo.rating)` 选档，题库检索沿用同一难度参数，用户无感知。

### 3.4 题型与可用性（辅助维度）
- `questionType`：`single` 单选 / `multiple` 多选 / `subjective` 主观（申论）。P1 只对客观题出题；
- `requiresImage`：图形推理、带图表的资料分析**不适合纯文本题库**，解析时识别并标记，出题检索默认过滤，P2 再支持人工补图后放开。

每题另带 `contentHash`（题干归一化后 sha1，库内唯一）与导入批次号。

## 4. 收录管线（管理端）

### 4.1 输入
- **P1**：粘贴长文本（整卷、题册复制均可）；
- **P2**：上传 `.txt / .md / .docx / .pdf / .xlsx`（docx 用 mammoth、pdf 用 pdf-parse 转文本；扫描版 PDF 走多模态 AI，成本另计）。

### 4.2 切分
题号正则切题（`/\n\s*(\d{1,3})[.、．]/`），选项 `A/B/C/D` 识别与校验；切分结果允许人工预览、删补后再送解析。

### 4.3 AI 批量解析（离线）
新增 prompt（`DEFAULT_BANK_IMPORT_TEMPLATE`，放 shared/src/ai/prompts.ts）：每次调用解析 5 题，输出 JSON 数组：

```json
[{
  "question_text": "题干含全部选项",
  "answer_text": "B",
  "analysis": "四段结构解析，缺解析可空",
  "subject": "判断推理",
  "primary_tag": "削弱加强",
  "extra_tags": ["论证结构"],
  "difficulty": "medium",
  "question_type": "single",
  "requires_image": false,
  "confidence": "high | medium | low"
}]
```

- `primary_tag` 要求从该科目系统标签清单中**精确选择**——做法复用 prompts.ts 里 `prefetchedTags` 的注入方式；
- `confidence: low` 的题强制进人工审核；
- 返回题数与切片数不符 → 整批标记待人工检查。

### 4.4 去重
1. `contentHash` 唯一约束挡精确重复；
2. `bigramSimilarity ≥ 0.6` 与库内同模块题比对（复用 smart 路由现成逻辑），命中标记 `duplicate` 待审。

### 4.5 审核状态机
`pending`（解析完成待审）→ `published`（可被出题） / `disabled`（下架）。管理员可编辑全部字段（改考点、改难度、修题干）。也提供"直接发布"开关信任 AI 结果（`low` 置信度仍强制审核）。

### 4.6 解析任务执行方式
学习端没有后台队列基建（scheduler.ts 只是简单函数库），**不引入新依赖**，采用分批推进：管理端点"开始解析"，前端按批（每批 5 题）顺序 POST，进度条展示"共 N 题 / 已完成 M / 待审 K"，可暂停、可关页后续跑（批次状态落库续跑）。每批独立走管理端限流。

## 5. 数据模型（prisma 增量）

```prisma
model BankQuestion {
  id            String  @id @default(cuid())
  subject       String              // 行测模块
  primaryTagId  String?
  primaryTag    KnowledgeTag? @relation("BankPrimaryTag", fields: [primaryTagId], references: [id], onDelete: SetNull)
  extraTagIds   String?             // JSON: 辅助考点 id 数组
  difficulty    String              // easy|medium|hard|harder
  questionType  String  @default("single")
  questionText  String
  answerText    String?
  analysis      String?
  requiresImage Boolean @default(false)
  source        String?             // 来源（文件名/出处），建议必填留痕
  status        String  @default("pending")   // pending|published|disabled
  contentHash   String  @unique
  duplicateOf   String?             // bigram 命中的疑似重复题 id
  importBatchId String?
  attemptCount  Int @default(0)     // 动态校准用
  correctCount  Int @default(0)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  practiceQuestions PracticeQuestion[]
  @@index([subject, status, difficulty])
  @@index([primaryTagId, status])
}

model BankImportBatch {
  id String @id @default(cuid())
  name String            // 文件名或"粘贴导入"
  totalCount Int @default(0)
  parsedCount Int @default(0)
  publishedCount Int @default(0)
  cursor Int @default(0)  // 分批推进的续跑游标
  status String @default("parsing") // parsing|parsed|done
  createdAt DateTime @default(now())
}
```

`PracticeQuestion` 增加：`bankQuestionId String?` + `bankQuestion BankQuestion?` 关联。做题记录经 `PracticeRecord.questionId → PracticeQuestion.bankQuestionId` 可追溯到题库题。

## 6. 出题链路改造

### 6.1 `/api/practice/smart`（薄弱点专项）——题库优先

定位考点（含 Elo 选难度）之后、组装 AI 锚文本**之前**插入检索：

```ts
// 1. 目标考点及子树
const tagIds = await collectTagSubtree(tagId);       // parent 递归
// 2. 用户已做过的题库题
const doneIds = await prisma.practiceQuestion.findMany({
  where: { userId, bankQuestionId: { not: null } },
  select: { bankQuestionId: true },
});
// 3. 检索：考点子树 ∩ published ∩ 非图形题 ∩ 难度(目标档±一档) ∩ 没做过
const bankHit = await prisma.bankQuestion.findMany({
  where: {
    primaryTagId: { in: tagIds },
    status: "published",
    requiresImage: false,
    difficulty: { in: adjacentDifficulties(difficulty) },
    id: { notIn: doneIds.map(d => d.bankQuestionId) },
  },
  orderBy: { createdAt: "asc" },   // 简单轮转：可加随机/最久未出优先
  take: 5,
});
const picked = bankHit[Math.floor(Math.random() * bankHit.length)];
```

- **命中**：直接 `practiceQuestion.create({ channel: "smart", bankQuestionId: picked.id, ... })`，响应带 `fromBank: true` 与 `meta.source: "bank"`。**从 10~60 秒降到毫秒级**；
- **未命中**：落到现有 AI 生成代码（原逻辑原样保留），生成结果照旧入库。

### 6.2 `/api/practice/generate`（举一反三）——P1 保留 AI
举一反三的价值在"锚定你的错题与错因"，题库题做不到个性化变式，P1 不动。P3 可加"AI 生成 + 同考点题库题"二选一由用户挑，或生成等待期先展示一道题库题垫场。

### 6.3 作答回写
`/api/practice/record` 中若 `question.bankQuestionId` 非空，`bankQuestion.attemptCount/correctCount` 自增，供难度校准与正确率展示。

## 9. 成本与风险

**成本**：解析一道题约 1~2k token（题干转录+分类+解析输出），按 DeepSeek 当前价格 1 万题约 10~30 元人民币，离线跑不赶时间；出题命中题库后**单次练习的 AI 成本降为零**。

| 风险 | 对策 |
|---|---|
| AI 解析错标（考点/难度/答案错误） | 审核状态机 + confidence 分级，low 强制人工审；真实作答正确率反向暴露错标 |
| 收录资源版权 | 仅收录自有权限资料，`source` 字段必填留痕；不对接公开题库爬取 |
| 图形/图表题无法纯文本收录 | `requiresImage` 导入即标、出题默认过滤，P2 补图机制 |
| SQLite 全局题库读写 | 单文件库读多写少，上述索引下万级题量无压力；上量后 Prisma 切 Postgres 无缝 |
| 同一用户重复见到同题 | `contentHash` 唯一 + 出题时用户已做 `notIn` 过滤 |
| 题库冷启动 | 未命中自动回退 AI 生成，系统行为与现状一致，题库可慢慢养 |

## 10. 后续讨论点（开工前需确认）

1. 行测考点树的粒度（每模块 8~15 个一级考点够用，还是细到二级）——影响 seed 工作量与 AI 分类准确率，建议 P0 先一级 + 常用二级；
2. 审核策略：先"逐题审核"保质量，还是先"直接发布 + 事后抽查"保速度；
3. 举一反三是否在 P3 接题库，或永远保持纯 AI 生成。
