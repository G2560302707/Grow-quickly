# 管理后台拆分方案（学习端 / 管理端 / 小程序）

> 目标：网页端与 uniapp 只保留学习功能；用户管理、系统配置、公告、反馈处理等一切管理功能拆到独立的管理后台网站；后续 uniapp 发布为微信小程序。
> 结论先行：**根目录保持学习端不动，新增 `admin/`（管理端 Next.js）+ `shared/`（共享包），npm workspaces 连接；uniapp 本轮零改动**。小程序作为独立 Phase 5。

---

## 1. 现状盘点

- 单个 Next.js 应用（根目录）同时承担：学习端页面、管理端页面（`/admin`、设置弹窗的管理标签页）、全部 API。
- uniapp（H5）只调学习类接口——已核对 `uniapp/src/api/index.ts`，**没有任何管理接口**，因此拆分对 uniapp 是零改动。
- 数据：SQLite（Prisma + better-sqlite3 adapter）；系统配置存文件 `config/app-config.json`（AI 供应商/实例、Prompts、SMTP、注册开关、超时）。
- 鉴权：NextAuth（JWT + Credentials），`User.role = "admin" | "user"`；middleware 只保护页面（matcher 排除了 `/api`），API 在各自路由内用 `getServerSession` + `requireAdmin` 校验。
- uniapp 已有 mp-weixin 编译目标位（manifest.json appid 为空），request 层已按"小程序自动维护 Cookie"设计。

## 2. 功能归属划分

### 2.1 移到管理端（admin/）

| 类型 | 内容 | 现位置 |
|---|---|---|
| 页面 | 仪表盘 + 用户管理 | `src/app/admin/page.tsx`、`src/app/admin/user/[id]/page.tsx` |
| 组件 | user-management、announcement-management、feedback-management | `src/components/admin/*` |
| 页面 | 系统设置（AI Provider/实例、Prompts、公告管理、反馈管理、邮件 SMTP、危险操作） | `src/components/settings-dialog.tsx` 中 admin 专属 tabs |
| 工具 | Prompt/公式调试页 | `src/app/latex-test/page.tsx` |
| API | `/api/admin/*`（dashboard、users、migrate-tags、system-reset） | 整体搬移 |
| API | `/api/settings`（GET 全量/POST）、`/api/settings/smtp-test` | 整体搬移 |
| API | `/api/ai/models`、`/api/ai/test` | 整体搬移 |
| API | `/api/announcements` 的写操作（POST/PUT/DELETE） | 搬写操作，GET 留学习端 |
| API | `/api/feedback` 的 GET / 处理状态更新 | 搬管理操作，POST 提交留学习端 |

### 2.2 学习端保留（web + uniapp 共用）

- 错题本全链路：notebooks、error-items（含 notes/mastery/geogebra）、analyze、reanswer、geogebra-analyze
- 练习全链路：practice/generate、smart、questions、record(s)、stats/practice、diagnosis/weakness、tags 全套
- 专注刷卷 focus、个人统计 stats、analytics（**注意：这是个人统计接口，不是平台统计，留在学习端**）、print-preview
- 账户：auth（NextAuth）、register(/status 读注册开关)、user（资料/改密）
- 个人数据：import、export
- 只读/提交类：announcements GET + read-all（红点通知）、feedback POST（提交反馈，uniapp 在用）、logs/frontend（端上日志采集）、version
- 设置弹窗瘦身：只留 **语言（本地存储）、账户（改名/改密）、关于** 三个 tab；"AI 超时"是全局配置，归管理端

### 2.3 顺手收紧的安全项

- 现状 `/api/settings` GET 对普通用户也返回掩码后的全量配置。拆分后学习端不再需要这个接口，新增一个只下发**非敏感项**（如 aiTimeout）的 `GET /api/settings/client`，密钥/SMTP/实例列表彻底不出学习端。

## 3. 目标架构

```
Grow quickly/
├─ package.json              # 根 = 学习端 Next.js（现不动），声明 workspaces: ["admin", "shared"]
├─ shared/                   # @grow/shared —— 两端唯一共享代码
│  ├─ prisma/                # schema.prisma + migrations + seed.ts（唯一权威副本）
│  └─ src/
│     ├─ prisma.ts           # 客户端单例（含 WAL pragma）
│     ├─ config.ts           # app-config.json 读写，路径改由 APP_CONFIG_PATH 环境变量指定
│     ├─ ai/                 # 供应商/实例/Prompts/tag-service（两端都要）
│     ├─ mailer.ts logger.ts auth-utils.ts api-errors.ts
│     └─ types/
├─ admin/                    # 管理端 Next.js，端口 3001
│  ├─ src/app/
│  │  ├─ login/              # 管理端独立登录页
│  │  ├─ page.tsx            # 仪表盘（由现 /admin 搬入）
│  │  ├─ users/ users/[id]/  # 用户管理
│  │  ├─ announcements/      # 公告管理
│  │  ├─ feedback/           # 反馈处理
│  │  └─ settings/           # AI / Prompts / 邮件 / 系统工具(重置、标签迁移、latex-test)
│  ├─ src/lib/auth.ts        # 独立 NextAuth：authorize() 拒绝 role !== "admin"
│  ├─ src/middleware.ts      # 保护全部页面；API 层仍用 requireAdmin 双保险
│  ├─ src/components/ui/     # 直接拷贝现有 shadcn primitives（不做过度抽象）
│  └─ Dockerfile
├─ uniapp/                   # 本轮不动；Phase 5 小程序化
└─ docker-compose.yml        # 新增 admin 服务，与 web 共挂 db 卷 + config 卷
```

### 关键设计决策

1. **不做大搬家**：学习端留在根目录，避免现有 import 路径、playwright/vitest 配置、Dockerfile 连锁改动；当前 `feature/p0-hardening` 分支还有大量未提交改动，渐进式拆分风险最低。以后想演进出标准 `apps/*` monorepo 再说，成本不高。
2. **共享策略**：只有"两端必须读到同一份"的东西进 shared（Prisma、app-config、AI 调用库、mailer、鉴权工具、错误结构）。学习域库（elo、diagnosis、smart-practice、tag-data、knowledge-tags 等）只有学习端用，留在原处不抽。
3. **鉴权**：管理端复用 `User` 表的 `role` 字段，但跑**独立 NextAuth 实例**，cookie 名改为 `admin.session-token`（与学习端 `next-auth.session-token` 互不干扰），`authorize()` 里非 admin 直接登录失败。middleware 兜底 + API 内 `requireAdmin` 双层。
4. **双进程共享 SQLite**：写库操作都是短事务，开启 WAL（在 `shared/src/prisma.ts` 连接时执行 `PRAGMA journal_mode=WAL`）后两进程同机并发没有问题。备份策略照旧（copy db 文件时注意 WAL）。
5. **配置文件并发**：`config/app-config.json` 通过 `APP_CONFIG_PATH` 指向同一份文件；**写者只有管理端**，学习端只读（注册开关、超时、AI 凭据供服务端调用），无并发写冲突。
6. **管理端 UI**：桌面优先、侧边栏布局，不复用学习端的移动端壳；组件库沿用现有 shadcn/tailwind 体系，拷贝一份 primitives 即可。

## 4. 分期实施

### Phase 0 — 收尾当前分支
`feature/p0-hardening` 上大量未提交改动先提交/合并，拆分工作另开分支，每期独立 commit 便于回滚。

### Phase 1 — 抽 shared 包（纯重构，行为零变化）
1. 根 `package.json` 加 `workspaces: ["shared", "admin"]`。
2. 建 `shared/`，把 `prisma/`（schema+migrations+seed）、`src/lib/{config,prisma,mailer,logger,auth-utils,api-errors}.ts`、`src/lib/ai/`、`src/types/api.ts` 移入，`shared` 包 `prepare` 脚本跑 `prisma generate`，提供 `@grow/shared` 导出。
3. 学习端 import 从 `@/lib/...` 改为 `@grow/shared`（机械替换，`next.config.ts` 加 `transpilePackages: ["@grow/shared"]`）。
4. `config.ts` 支持环境变量 `APP_CONFIG_PATH`（默认 `cwd/config/app-config.json`，学习端行为不变）。
5. 验收：`npm run build`、`npm run test`（unit+integration）、e2e 全绿；功能无任何变化。

### Phase 2 — 管理端骨架
1. `admin/` 新建 Next.js：独立 auth（admin-only）、login 页、侧边栏 layout、middleware。
2. Dockerfile + compose 服务（端口 3001，挂同一 db/config 卷）。
3. 验收：admin 账号能登录管理端；普通用户登录被拒；学习端 cookie 与管理端互不影响。

### Phase 3 — 功能搬移（按依赖顺序，逐个 commit）
1. **用户管理**：`/api/admin/users*` + 组件 → admin；学习端删除。
2. **仪表盘**：`/api/admin/dashboard` + `/admin` 页面 → admin。
3. **公告**：`/api/announcements` 拆分——写操作迁 admin，学习端保留 GET + read-all。
4. **反馈**：GET/处理迁 admin，学习端保留 POST。
5. **系统设置**：`/api/settings`、`smtp-test`、`/api/ai/*`、settings-dialog 管理 tabs、danger 工具（system-reset、migrate-tags、latex-test）→ admin；学习端设置弹窗瘦身，新增 `GET /api/settings/client`。
6. 学习端删除 `/admin` 页面与 middleware 的 admin 检查（管理端 API 已不存在于学习端，普通用户无攻击面）。
7. 测试随迁：admin 相关 integration tests → `admin/`；学习端 e2e 移除 admin spec，admin 新增最小 e2e（登录、封禁用户、发公告）。
8. 更新 `启动测试.bat`/`停止服务.bat`/README 为四端（web / admin / uniapp / db）。
9. 验收：学习端普通用户全流程回归（登录→拍照识题→练习→专注→统计→导入导出→反馈提交→公告红点）；admin 全功能回归。

### Phase 4 — 部署收尾
- compose 校验：admin 与 web 共享卷挂载、`NEXTAUTH_SECRET`/`DATABASE_URL`/`APP_CONFIG_PATH` 环境变量对齐。
- 生产建议：管理端只在内网/VPN 或加 IP 白名单暴露，学习端公网正常暴露。

## 5. Phase 5 — uniapp 小程序化（微信）

1. **域名（前置硬条件）**：request 合法域名必须是 **HTTPS + ICP 备案** 的域名（现在是 `http://localhost:3000` 占位）。现有 Cloudflare Tunnel 思路可沿用，但域名要备案并在小程序后台配置；无备案域名则只能用开发版"不校验合法域名"自用。
2. **登录态**：现设计依赖"小程序运行时自动维护 Cookie"（NextAuth 会话）。**真机先验证**；若 Set-Cookie 回传不稳，兜底方案：后端加 `POST /api/auth/token`（校验账密后签发 JWT，复用 NEXTAUTH_SECRET），`request.ts` 统一带 `Authorization: Bearer`，API 鉴权层兼容两种方式。
3. **组件适配**（工作量主要在这）：
   - `MdView`：KaTeX 数学公式在小程序 `rich-text` 无法直接渲染——按内容分级：考公行测以文字题为主可先降级为纯文本；数学公式确有需求再引入 towxml 或公式转图片方案。
   - `stats.vue` 图表：确认实现是否用 canvas/echarts，小程序端换 uCharts / qiun-data-charts。
   - tabBar 图标已是 png，直接可用；`uni.request` 的 PATCH 方法真机验证，不行就在后端补 POST 别名（request.ts 已留注释）。
4. **合规（上架必过）**：
   - 类目：个人主体教育类目受限，考公刷题按"工具-效率"类目提交更稳；有企业主体可选教育类目。
   - UGC 安全：反馈内容接入 `security.msgSecCheck`；AI 生成题目展示建议接入内容安全检测（文本安全 API），审核会盯 UGC/AIGC。
   - 配置《用户隐私保护指引》（收集邮箱/昵称/密码的声明），否则接口审核被拒。
5. **体验细节**：小程序分包（页面不多可暂不分包）、分享卡片、下拉刷新已在 pages.json 中配置过。

## 6. 风险清单

| 风险 | 缓解 |
|---|---|
| shared 抽取引入隐性行为变化 | Phase 1 不改任何逻辑，仅搬文件+改 import，全量测试兜底 |
| SQLite 双进程写冲突 | WAL + 短事务；管理端写频极低 |
| 管理端误上公网 | compose 默认只绑内网端口；文档写明 |
| 小程序 Cookie 登录不稳 | Phase 5.2 的 token 兜底方案 |
